# API overview

Internal service paths begin `/v1`; external/browser paths prepend the gateway base. Every service provides `GET /health` and `GET /ready`. Successful JSON is the entity/list schema in its OpenAPI file; malformed bodies, invalid UUID/date/query values, and invalid state return 400; an absent entity returns 404; unexpected failures return a safe 5xx error envelope.

Every write (`POST`, `PUT`, `PATCH`, `DELETE`) to Finance, Tasks, Inbox, Calendar, Calendar feeds, Food, Recipe import, Voice, Notifications, Banking, or Backup must say who makes it in the `X-Life-OS-Actor` header: `user` (the owner; the Dashboard sends it), `agent:<name>` (the Life OS AI), `system:<name>` (a Life OS component), or `dev:<name>` (a development tool or agent, for example `dev:claude-code`). Names are 1–64 letters, digits, `.`, `_`, or `-`. A write without a valid actor returns 400 with error code `actor_required`; nothing is recorded as the owner by default. Reads need no actor. Through the gateway only `user` and `dev:<name>` are accepted; `agent:`/`system:` claims are dropped. See [Activity](../services/activity.md#actors).

Examples, run as a development tool (`dev:curl`; never send `user` from a tool):

```sh
curl -X POST http://127.0.0.1:3000/api/tasks/v1/tasks -H 'X-Life-OS-Actor: dev:curl' \
  -H 'content-type: application/json' -d '{"title":"Pay invoice"}'
curl -X POST http://127.0.0.1:3000/api/inbox/v1/inbox-items -H 'X-Life-OS-Actor: dev:curl' \
  -H 'content-type: application/json' -d '{"content":"Call insurer","source":"manual"}'
curl -X POST http://127.0.0.1:3000/api/calendar/v1/events -H 'X-Life-OS-Actor: dev:curl' \
  -H 'content-type: application/json' -d '{"title":"Holiday","allDay":true,"startDate":"2026-12-24","endDate":"2026-12-24"}'
```

A Finance manual transaction needs only `amount` (`{amount,currency}` in minor units): without `accountId` it goes to the built-in Cash account and without `bookingDate` it is dated today in the owner's timezone. CSV requests use `text/csv` and name the account in `accountId`. Task creation requires `title`; Calendar creation requires `title` and `allDay` (plus `startAt`/`endAt` instants or `startDate`/`endDate` dates), and Calendar reads compare all-day dates in the `timeZone` parameter, defaulting to `LIFE_OS_TIMEZONE`; Inbox creation requires `content` and `source`. A Voice upload is multipart field `audio` plus optional `source` and JSON `sourceMetadata`; it is queued rather than transcribed inline, and the upload's `sourceMetadata` is carried over to the resulting Inbox item. An Inbox item's `sourceMetadata.timeZone` (an IANA name, sent by the Dashboard with text and voice captures) is the timezone its relative dates are planned in. Inbox's optional `dedupeKey` makes retried Voice handoffs idempotent. Exact request/response schemas, pagination, filtering, and validation are versioned in `services/*/api/openapi.yaml`.
