# MCP and AI

The Go MCP service is available behind `/api/mcp/mcp` using streamable HTTP, with `/api/mcp/health` and `/api/mcp/ready` probes. Its typed read tools call Finance monthly summary/transactions, Tasks list, Inbox list, and Calendar list through the services' HTTP APIs. It also provides the narrowly scoped mutation tools used by Inbox processing: `task_create`, `calendar_create`, `inbox_start_processing_attempt`, `inbox_record_processing_attempt`, and `inbox_resolve`. It never owns or queries Finance, Tasks, Inbox, or Calendar tables directly; upstream failures become understandable MCP tool errors.

The non-interactive processor uses the existing local Codex CLI/ChatGPT login, not an API key. It is configured by `LIFE_OS_CODEX_COMMAND` and `LIFE_OS_CODEX_MODEL` (default `gpt-5.6-terra`, a lower-cost alternative to Astra); it is intentionally separate from domain handlers and targets the MCP endpoint, not service databases.

Run `go run ./cmd/processor` from `services/mcp` to process raw Inbox items. The processor reads them through `inbox_list`, asks Codex for a constrained JSON plan, accepts only high-confidence task/event creation actions, records each attempt through MCP, and resolves an item only after every action succeeds. Ambiguous, malformed, unsupported, low-confidence, and failed plans are retained in the Inbox with a `retryable` audit result. It will not propose finance mutations or calendar updates/deletions, and it skips an item whose deterministic idempotency key already has a processed attempt. `go run ./cmd/processor --dry-run` returns proposed MCP actions without creating attempts, mutating core services, or resolving Inbox items. `go run ./cmd/processor --content '...'` is a separate non-mutating diagnostic that prints only Codex's proposed JSON plan.
