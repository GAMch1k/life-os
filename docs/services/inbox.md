# Inbox service

Inbox is the capture queue in `inbox_db`. It stores user content, source (`manual`, `web`, `voice`, `watch`, or `email`), metadata/media references, and a lifecycle: `raw` → `processing` → `resolved` or `discarded`. It intentionally does not decide whether a capture becomes a task, event, or transaction. Processing attempts are kept separately with a per-item idempotency key, agent/model identity, attempted actions, timestamps, and retryable/failed/processed outcome; raw content is never consumed or overwritten.

An ambiguous or low-confidence Task mutation becomes `human_review`, rather than an automatic retry. The Inbox item retains the original capture, proposed action, reason, and candidate Tasks in `processingMetadata`; it is excluded from the processor's raw-item poll. The Dashboard Human Review queue calls `POST /v1/inbox-items/{itemId}/human-review/resolve` with one retained candidate ID. Inbox verifies that selection, stores an approved action, returns the item to `raw`, and the processor resumes it through MCP and the owning Tasks API. The item resolves only after that mutation succeeds. `retryable` remains reserved for temporary technical failures; `failed` means recovery is exhausted or operator intervention is needed. `make human-review-smoke` proves the automatic ambiguous-capture → Human Review → selected Task → persisted completion → resolved Inbox chain in disposable Compose resources.

The current dashboard captures and resolves/discards items. The automatic MCP/Codex processor reads raw items only through MCP, preserves an audit trail, handles ambiguity safely, and calls core APIs through MCP tools. Its processing lifecycle is `raw → processing → resolved`, with a retryable or failed attempt returning the item to `raw`. Each retry creates a distinct audit attempt key (`<operation>.retry.<n>`), preserving the original attempt and avoiding the former uniqueness collision; a processed attempt for the same deterministic operation prevents later duplicates. Invalid requests return 400 and missing items 404; readiness is at `/ready`. Test with `make db-test SERVICE=inbox` and `make e2e-smoke`.
