# Tasks service

Tasks owns actionable work in `tasks_db`: title, optional notes/due date, completion timestamps, and optional daily/weekly/monthly recurrence. It accepts dashboard/API input and returns Task JSON; it does not interpret Inbox items or access any other database. Gateway base: `/api/tasks`.

Create/list tasks, patch editable fields, then use the explicit completion and reopen actions. An open Task may have no `dueAt`: it remains a valid, findable Task and no artificial date is assigned. To intentionally return a scheduled Task to Unscheduled, send `clearDueAt: true` to `PATCH /v1/tasks/{taskId}`; it cannot be combined with `dueAt`. A `dueBefore` listing includes undated Tasks by default so attention views do not hide them; clients that need a strict scheduled-date-only result send `includeUndated=false`. Input limits and date/recurrence validation produce 400; unknown UUIDs produce 404. A create request with `Idempotency-Key` persists its payload identity: repeating the same request returns the original Task, while the same key with a different payload returns 409. `/health` and `/ready` support operations. MCP calls these APIs, never tables.
